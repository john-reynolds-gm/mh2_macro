Gap Auditor Architecture

How data moves from source files to writers, and where the two SQLite databases sit. One database is rebuilt from source on every start. The other holds writer judgments and has no other copy.

Process Rebuilt from source; safe to lose Durable; must survive restarts and be backed up Persistent storage boundary

Two databases, two rules

FileRole
mh2.db
disposable		Built from the source files. Rebuilt on every container start. The app opens it read-only. Losing it costs one rebuild.
mh2_seq.db
durable		Writer judgments. Created once, never deleted or rebuilt. This is the only file that needs persistent storage and backups.

Both are SQLite files. No separate database server is involved.

What happens at startup

  1. rebuild.py builds mh2.db from the source files. A failed build leaves the previous copy in place.
  2. render_static.py writes coverage.html from mh2.db.
  3. uvicorn starts review_api.py on port 8080.

Startup makes no network calls. mh2_seq.db is created if missing and otherwise left alone.

What this needs from hosting

One instance, one worker. Two instances would mean two copies of mh2_seq.db that drift apart, or one file shared over the network, where SQLite locking is unreliable.

Local persistent disk for mh2_seq.db, kept across restarts and redeploys. An Azure Files (SMB) share is a poor fit for SQLite.

Scheduled backups of mh2_seq.db. Nothing else needs backing up.

Read-only SharePoint access later, via Graph Sites.Selected, to pull source files at rebuild time.

The data folder location is set by one environment variable, MH2_DATA_DIR, so it can point at whatever persistent storage IT provides. Source: Dockerfile, entrypoint.sh, scripts/rebuild.py, review_api.py, config.py.
